## Design agenda

In a suggested order. Each topic is expected to produce decisions, capability lines or open items in the catalog.

1. **IR specification.** The detailed specification of what [D41]({workspace}/decisions/Platform#41) decided: the document schema and its migrations, the YAML subset, the three-way merge on the semantic model, the layout sidecar, the CEL environment and function library, value outputs and run rules; split semantics for leakage prevention ([DS 2.8](05-capabilities-ds.md)); and the node-type contract, including declared runtime, execution modes, supported dialects, declared grouping keys, memory class, order dependence, output-schema mode and value outputs ([D27]({workspace}/decisions/Platform#27), [D34]({workspace}/decisions/Platform#34), [D41]({workspace}/decisions/Platform#41)); commentable collections keyed by stable identifier ([D44]({workspace}/decisions/Platform#44)); and the control-flow constructs of [D46]({workspace}/decisions/Platform#46): carried state, the loop scope, branch joins, the switch, loop execution modes and column selectors; the exact run outcome rule and how a fused unit's resource request combines the needs of its segments ([D47]({workspace}/decisions/Platform#47)). It is frozen before any external user commits IR to git.
2. **Execution backends.** The backend interface in detail; Kubernetes and Slurm adapters; the agent protocol as recorded in [D40]({workspace}/decisions/Platform#40), [D44]({workspace}/decisions/Platform#44) and [D48]({workspace}/decisions/Platform#48); source probes and the connector `probe` function ([D49]({workspace}/decisions/Platform#49)); image building and registries in the customer's environment ([CORE 1.10](03-capabilities-core.md), [D22]({workspace}/decisions/Platform#22)); job tagging on every backend ([CORE 4.8](03-capabilities-core.md)); units spanning several containers for training across machines ([MLE 2.1](06-capabilities-mle.md)).
3. **Warehouse adapter.** The interface covering pushdown, extraction to Arrow, publication ([D15]({workspace}/decisions/Platform#15)), time-travel replay ([D4]({workspace}/decisions/Platform#4)), credential minting ([D22]({workspace}/decisions/Platform#22)), connection policy ([D28]({workspace}/decisions/Platform#28)) and query tagging; the Snowflake implementation; the conformance-matrix harness and CI accounts.
4. **Node SDK and palette.** The built-in palette per discipline with each node assigned to an Ibis-first tier ([D27]({workspace}/decisions/Platform#27)); the plugin SDK; UI forms from parameter schemas, including column selectors ([D46]({workspace}/decisions/Platform#46)); fixed-column pivots and ordered aggregates implemented in forms that spill ([D27]({workspace}/decisions/Platform#27), [D47]({workspace}/decisions/Platform#47)).
5. **Visual builder UX.** Canvas behavior; sample-then-scale ([DS 1.4](05-capabilities-ds.md)), previews, sessions, sandboxes and the comparison with production ([D50]({workspace}/decisions/Platform#50)); showing units and fusion; plan, engine, placement and capacity-check visibility, including extraction suggestions and pinned-plan differences; fused-node inspection; drafts, commits and deploying ([D45]({workspace}/decisions/Platform#45)).
6. **Security and identity.** Authentication; custom roles and attribute-based policy beyond the fixed roles of [D45]({workspace}/decisions/Platform#45); secrets; the choice of an RFC 9421 implementation in Go and signing as a wrapper around ConnectRPC ([D52]({workspace}/decisions/Platform#52)); sandboxing of untrusted containers ([CORE 7.6](03-capabilities-core.md)); audit.
7. **Technology stack selection.** The items still undecided in the [technology table]({workspace}/documentation/Platform#4.3): authentication and identity, observability, and image building and registries. The minimum stack is recorded in [D44]({workspace}/decisions/Platform#44).
8. **Observability implementation.** Logs, metrics, events, alerting, cost attribution ([CORE 4.5](03-capabilities-core.md), [S22](07-open-items.md#7.22)).
9. **Discipline specifics.** DE (connectors, CDC, SCD, idempotent writes); DS (leakage prevention, tuning loops per [DS 3.6](05-capabilities-ds.md)); MLE (the point-in-time join node of [D38]({workspace}/decisions/Platform#38), approvals, retraining loop, checkpointing per [MLE 2.3](06-capabilities-mle.md)).
10. **Reproducibility implementation.** Verification policy ([S2](07-open-items.md#7.2)), comparator plugins, run bundles ([CORE 5.6](03-capabilities-core.md)).
11. **APIs.** The public API over ConnectRPC, including whether and when a resource-style REST surface is added through Vanguard ([D44]({workspace}/decisions/Platform#44)); CLI; SDK.
12. **Business model and open-core line.** The inventory of extension points, the split into modules and the classification of the first slice ([D53]({workspace}/decisions/Platform#53)); the license, contributor terms and the full line, by the deadline set in [D5]({workspace}/decisions/Platform#5).
13. **Non-functional requirements.** Scale targets beyond those set in [D43]({workspace}/decisions/Platform#43), archiving ([S5](07-open-items.md#7.5)), SLAs, availability; cells, each with its own database and a set of tenants, as the route for scaling a hosted control plane ([D47]({workspace}/decisions/Platform#47)).
14. **Roadmap and phasing.** Beyond the first development slice ([D29]({workspace}/decisions/Platform#29)): v1, then v2, including whether and when a hosted control plane is operated.
15. **Open items.** [S1](07-open-items.md#7.1)–S3, [S5](07-open-items.md#7.5)–[S8](07-open-items.md#7.8), [S15](07-open-items.md#7.15)–[S17](07-open-items.md#7.17), [S19](07-open-items.md#7.19)–[S23](07-open-items.md#7.23) and [S25](07-open-items.md#7.25).
