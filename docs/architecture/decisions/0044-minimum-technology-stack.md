## Context

**Go for the control plane and the agent** (D44). The control plane evaluates user expressions without running user code, and the reference implementation of CEL, with static and runtime cost limits, is in Go; a single in-memory scheduler suits Go's concurrency; and the agent must ship as one static binary to HPC and air-gapped hosts. Python would have matched the unit runtime and offered the most capable comment-preserving YAML library, at the cost of scheduler throughput and a heavier single-machine installation. Ibis compiles inside units, so it does not constrain the choice ([D27](0027-ibis-for-relational-node-definitions.md)).

**ConnectRPC rather than REST** (D44). REST with OpenAPI was considered for both the interface and the agent. On the wire the agent protocol is the same either way, unary calls and a long-poll over HTTPS, but with protobuf, compatibility across the window of agent versions and the tagged unions of [D40](0040-protocol-between-the-control-and-data-planes.md) and [D42](0042-catalog-persistence.md) are properties of the schema rather than of CI checks and uneven code generators. A resource-style REST surface can still be generated from the same definitions. A gRPC bidirectional stream was rejected because enterprise proxies may not carry long-lived HTTP/2 streams.

**Key identity rather than certificate identity** (D44). Proxies that inspect TLS cannot carry client certificates, so mutual TLS alone would require the regulated customers that hybrid deployment is aimed at to exempt the control plane from inspection. Making the enrolled key the identity, proven by signed messages in every deployment ([D52](0052-agent-identity-by-message-signatures.md)), removes that precondition. Responses are signed as well as requests, because leases carry image digests and credential scopes that an intercepting proxy could otherwise alter.

**The Iceberg projection as a unit, replaying every version** (D44). Inside the agent the projection would have avoided a container start per commit, but customers upgrade agents on their own schedule, so fixes to a pre-1.0 library would reach them late; batching runs recovers most of the cost. Coalescing each run to the latest version was rejected because it hides intermediate versions from external time travel while saving only metadata.

**Projection on by default** (D44). The projection tracks nothing the platform needs: tracking, partitions, replay and backfill rest on the platform's catalog, for every dataset family ([D42](0042-catalog-persistence.md)). It is the safe way for external engines to read managed data, which would otherwise expose superseded and quarantined files, and it is standard practice rather than a reproducibility cost, so [D36](0036-data-engineering-practice-first-reproducibility-by-choice.md) argues for it. Only restricted data is held back, because catalogs that vend storage credentials can widen access beyond bucket permissions.

**Comment preservation deferred** (D44). Preserving comments on canvas write-back was judged not worth building for the first slice. It remains cheap to add later because commentable collections in the IR are keyed by stable identifier, so comments can be carried by path; the canvas warns before a save would remove them.

The reasoning on source probes in the data plane, in [D49](0049-source-probes.md), also cites this decision.

## Decision

The languages, interfaces, tooling and libraries the first slice is built with; the transport and the proofs of agent identity left open by [D40](0040-protocol-between-the-control-and-data-planes.md); the tooling checks left by [D41](0041-ir-text-form-round-trip-and-structure.md); and the library, storage format, catalogs and defaults of the Iceberg projection of [D42](0042-catalog-persistence.md).

- **Languages.** The control plane and the agent are written in Go. The reference implementation of CEL is in Go, with static cost estimation and runtime cost limits ([D41](0041-ir-text-form-round-trip-and-structure.md)); a single active scheduler holds its state in memory ([D43](0043-scheduling-and-capacity.md)); and the agent ships as one static binary for HPC login nodes and air-gapped hosts ([D22](0022-deployment-topologies.md)). Unit runtimes are written in Python, which Ibis, DuckDB and Polars require ([D27](0027-ibis-for-relational-node-definitions.md)), with one CPython version pinned per base-image release.
- **Database.** PostgreSQL 17 or later, the first release with `transaction_timeout` ([D42](0042-catalog-persistence.md)).
- **Migrations.** goose, with plain SQL migrations embedded in the binary, forward-only, and run under an advisory lock at start-up or by an explicit command. Each release's schema remains compatible with the previous release's code (expand, then contract), so a hosted control plane can be upgraded in place and a self-hosted installation that skips releases applies the migrations in order.
- **Interfaces.** Protobuf with ConnectRPC for the web application, the CLI, the agent protocol and the local agent–unit contract, as separately versioned packages for the three contracts of [D40](0040-protocol-between-the-control-and-data-planes.md). `buf breaking`, at the WIRE_JSON level or stricter, gates every change. The Connect protocol works over HTTP/1.1 and HTTP/2, accepts JSON and is compatible with gRPC. Live state reaches the browser through server streaming, with polling as the fallback behind buffering proxies. A resource-style REST surface for the public API can be added later by Vanguard transcoding from annotations on the same definitions (design agenda).
- **Agent transport.** State-bearing messages are unary, idempotent calls ([D40](0040-protocol-between-the-control-and-data-planes.md)). Each agent replica holds one long-poll, which returns offered work and control signals such as cancellation and maintenance tasks. Nothing depends on long-lived HTTP/2 streams, which enterprise proxies may not carry. Cancellation reaches an agent within about one round trip while its long-poll is open, and within one heartbeat at worst ([D43](0043-scheduling-and-capacity.md)).
- **Agent identity.** Amends [D40](0040-protocol-between-the-control-and-data-planes.md). An agent's identity is possession of its enrolled key, proven by HTTP Message Signatures (RFC 9421) on every request and response, with bodies covered through Content-Digest (RFC 9530) ([D52](0052-agent-identity-by-message-signatures.md)). The agent pins the control plane's signing key at enrollment. Replays are handled by the existing idempotency and per-attempt sequence numbers together with server-issued nonces, never by wall-clock time.
- **Frontend.** React and TypeScript, built with Vite as a single-page application served by the control-plane binary, so the single-machine deployment needs no separate web server. The canvas uses React Flow 12. Workflows without a layout sidecar ([D41](0041-ir-text-form-round-trip-and-structure.md)) are laid out by ELK, which handles nested frames for maps and loops; ELK's license, EPL-2.0, is noted for the license decision ([D5](0005-distribution-and-tenancy.md)).
- **YAML.** Amends [D41](0041-ir-text-form-round-trip-and-structure.md). The parser is goccy/go-yaml. Comments are not preserved when the canvas writes a workflow back in the first slice, and the canvas warns before a save would remove them. Commentable collections, such as nodes, ports, parameters and dataset declarations, are keyed by stable identifier rather than held as lists, so that preservation can be added later without changing the shape of committed files.
- **CEL.** Amends [D41](0041-ir-text-form-round-trip-and-structure.md). The control plane evaluates expressions with cel-go, with a cost limit on every program. How the canvas checks expression types is settled with the visual builder; the default is a check call to the control plane, so that the canvas and the evaluator cannot disagree.
- **Iceberg projection.** Amends [D42](0042-catalog-persistence.md). A platform maintenance unit using PyIceberg at a pinned version, driven by the outbox. As a unit, the projection reaches every deployment through the image the control plane selects, without waiting for customers to upgrade their agents ([D40](0040-protocol-between-the-control-and-data-planes.md)), and reuses leases, fencing, scoped credentials and retries. Runs are batched, and each run replays every version that became current since the previous run as its own Iceberg snapshot, in commit order, so that external history matches the platform's within retention. Quarantined versions, and released versions older than the current version, are not projected ([D31](0031-execution-state-model.md)). Snapshot properties carry the dataset identifier, version number and commit time; snapshot timestamps record the time of projection, so exact as-of reads go by version or through the platform ([D38](0038-point-in-time-retrieval.md)). Projection is serialized per dataset. Superseded files are replaced by a delete on a partition predicate and the addition of the new files in one transaction, and a run that would rewrite any data file fails instead. A rebuild operation regenerates a projection from the catalog. iceberg-go, run as a unit, is the fallback.
- **Tabular storage.** Managed tabular datasets on object storage are stored as Parquet with column statistics written, and every partition key is stored as a column, as the Iceberg specification requires of writers; a dataset partitioned by ingestion time therefore carries an ingestion column written at extraction ([D38](0038-point-in-time-retrieval.md)); adopted files whose partition key exists only in their path are the one exception, and are not projected ([D51](0051-adoption-of-existing-data.md)). Partitions keep their own time zone ([D13](0013-partitioning-intervals-and-dataset-ownership.md)) through identity transforms on the stored key rather than through Iceberg's day and hour transforms, which for timestamps with a time zone operate on UTC values. Projected tables use Iceberg format version 2; timestamps are written at microsecond precision unless a schema declares nanoseconds, in which case that dataset is projected as version 3; unsigned integers are widened; and a dataset with a type Iceberg cannot represent is not projected, with the reason shown. A tabular upload is projected through its derived Parquet copy, never its original ([D4](0004-datasets-as-first-class-objects.md)).
- **Catalogs.** The first slice supports REST catalogs, which include AWS Glue's Iceberg endpoint with SigV4 signing, and the SQL catalog in a database the customer provides, never the platform's own Postgres ([D40](0040-protocol-between-the-control-and-data-planes.md), [D42](0042-catalog-persistence.md)). The catalog is configured on the storage target under a logical name ([D4](0004-datasets-as-first-class-objects.md), [D41](0041-ir-text-form-round-trip-and-structure.md)), with secret references. The namespace is an optional prefix followed by `project.path`, and the table takes the dataset's `name` ([D19](0019-stable-dataset-identity.md)). Each table carries the dataset's identifier as a property. The projection never takes over a table it did not create, and if an external writer commits to a projected table it stops projecting that dataset and flags it. Iceberg snapshots are expired before platform garbage collection removes their files, and a deleted dataset's table is dropped without purging files. Native Glue, Hive Metastore and file-only catalogs follow.
- **Projection by default.** Wherever a catalog is configured, every managed tabular dataset is projected: external readability of managed data is standard practice, not a reproducibility cost ([D36](0036-data-engineering-practice-first-reproducibility-by-choice.md)). An owner may opt a dataset out. Datasets classified restricted or above are not projected unless their owner allows it, which is recorded for audit, because catalogs that vend storage credentials can extend read access beyond bucket permissions ([D30](0030-tenancy-and-isolation-enforcement.md), DE 5.9). Amended by [D45](0045-isolation-enforcement-and-role-model.md): allowing it requires the owner to hold restricted clearance. A dataset that is not projected shows why.
- **Not the source of truth.** The projection serves external engines only. Tracking, partition validity, replay and backfill rest on the platform's catalog for every dataset family ([D14](0014-input-version-resolution.md), [D20](0020-backfill-commits-and-scheduling.md), [D42](0042-catalog-persistence.md)). A managed dataset whose storage target is a lakehouse table, including a table taken over in place ([D51](0051-adoption-of-existing-data.md)), commits through that table's format instead and is not projected ([D15](0015-atomic-publication.md)).
- **Condition.** An interoperability suite checks that projected tables are read correctly by DuckDB, Spark, Trino and PyIceberg, including partition values, time zones, name mapping and type mapping. It runs first as a spike before the projection is built and is then kept in CI. A failure moves the implementation to the fallback; it does not reopen the decision.
- **Amends.** [D4](0004-datasets-as-first-class-objects.md): a tabular upload has a derived Parquet copy where projection is on, and the copy is what is projected. [D13](0013-partitioning-intervals-and-dataset-ownership.md) and [D38](0038-point-in-time-retrieval.md): a dataset partitioned by ingestion time carries the ingestion time as a column. [D23](0023-artifact-storage-layout.md) and [D42](0042-catalog-persistence.md): files of a projected dataset are deleted only after the Iceberg snapshots that reference them have expired. [D25](0025-processing-engines-and-runtimes.md): managed tabular datasets on object storage are stored as Parquet. [D30](0030-tenancy-and-isolation-enforcement.md): restricted datasets are held back from external catalogs. [D31](0031-execution-state-model.md) and [D43](0043-scheduling-and-capacity.md): cancellation reaches an agent within about one round trip. [D40](0040-protocol-between-the-control-and-data-planes.md): the transport is settled, and identity becomes possession of the enrolled key. [D41](0041-ir-text-form-round-trip-and-structure.md): the YAML parser and the CEL implementation are chosen, and comment preservation is deferred. [D42](0042-catalog-persistence.md): the projection's library, history, storage format, catalogs and defaults are set.
- **Remaining.** The authentication and identity provider, the observability stack, and the image builder and registry are settled when the work reaches them (design agenda).
- **Sandboxes.** Amended by [D50](0050-development-mode.md): sandbox versions are never projected.

## Rejected alternatives

- REST with OpenAPI for both the interface and the agent, under which compatibility across agent versions and the tagged unions of [D40](0040-protocol-between-the-control-and-data-planes.md) and [D42](0042-catalog-persistence.md) would rest on CI checks and uneven code generation rather than on the schema language.
- A gRPC bidirectional stream for the agent, which depends on long-lived HTTP/2 streams.
- The projection inside the agent with iceberg-go, which would tie projection fixes to customers' agent upgrades.
- Projecting only the latest version in each run, which would hide intermediate versions from external time travel.
- Projection enabled only by administrators.
