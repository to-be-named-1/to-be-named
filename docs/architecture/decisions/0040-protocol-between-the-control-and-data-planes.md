## Context

**The agent as single egress** (D40). Letting unit runtimes talk to the control plane directly was rejected: credentials are minted and classification is enforced in the customer environment, which needs one controlled exit point. Agents do not stop attempts at ordinary lease expiry, because a control-plane outage must not fail running work; side effects are instead guarded by a lease check and task-run idempotency keys, and a long hard limit bounds wasted compute.

The reasoning on ConnectRPC rather than REST, in [D44](0044-minimum-technology-stack.md), and on lease renewals in memory, in [D48](0048-execution-mechanics.md), also cites this decision.

## Decision

The data plane is driven by pull-based agents connecting outward to the control plane, designed to hybrid requirements in every deployment so that topologies differ only in where the control plane runs ([D22](0022-deployment-topologies.md), [D29](0029-first-development-slice.md)). Each agent enrolls once; each attempt is then claimed, launched, renewed, reported on, committed and ended through the messages below. Timings were set by [D43](0043-scheduling-and-capacity.md), and the transport and the proofs of identity by [D44](0044-minimum-technology-stack.md).

- **Single egress.** A unit runtime talks only to its local agent, through a local endpoint; containers have no route to the control plane. The agent is the single point at which data-plane traffic leaves the customer environment, which is where credentials are minted ([D22](0022-deployment-topologies.md)) and classification is enforced. The agent is therefore on the hot path and is deployed for high availability.
- **Credentials and secrets.** Leases carry credential scopes — the storage paths a unit may read and write ([D23](0023-artifact-storage-layout.md)) — and references to secrets, never credentials or secret values. The agent mints short-lived storage credentials from the customer's identity and resolves secrets from the customer's secret manager. Self-hosted installations without a secret manager use a built-in secret store running on the data-plane side. This applies in every deployment.
- **Outage and partition.** Lease expiry is judged only on the control plane's clock and only while it is running. After a restart, the control plane allows a grace period of at least one lease duration before declaring any lease lost, so its own outage does not fail running work ([D21](0021-architecture-planes.md)). Lease durations are relative to receipt, never absolute timestamps. An agent partitioned while the control plane stayed up has its leases expire and its late commits fenced.
- **Stale attempts and side effects.** Fencing protects platform commits ([D15](0015-atomic-publication.md)) but not external systems ([CORE 2.12]({workspace}/documentation#3)). A side-effecting step first confirms that its lease is live, so side effects pause during a control-plane outage, and uses idempotency keys derived from the task run rather than the attempt, so a duplicate from a stale attempt is deduplicated where the external system supports such keys. Agents do not stop attempts at ordinary lease expiry; an attempt that has not renewed for a configurable hard limit of several lease durations is stopped, bounding wasted compute without killing work during short outages.
- **Durable commits.** Every commit request can be rebuilt from the attempt's staged manifest, already durable in attempt-scoped staging ([D15](0015-atomic-publication.md)). The agent's buffer sits on a durable volume but is only a cache, so any replica can resubmit. Commit requests are idempotent, keyed by attempt and request identifier, and a replay always receives the same answer: committed or fenced.
- **Placement.** The planner assigns every unit to an agent pool — one backend in one region — and agents claim only their own pool's leases, so pulling never moves placement decisions to agents ([D26](0026-placement-constraints.md), Seam 3). Agents report their capabilities at enrollment and on every connection: backend type, region ([D26](0026-placement-constraints.md), Seam 1), capacity ceilings ([D34](0034-capacity-and-size.md)), processor architectures and supported protocol versions. Fair-share ordering happens in the control plane.
- **Identity.** An agent enrolls once with a one-time enrollment token, generates a key pair and registers its public key, bound to its tenant and pool ([D30](0030-tenancy-and-isolation-enforcement.md)); possession of the enrolled key is the agent's identity ([D44](0044-minimum-technology-stack.md)), proven by signed requests and responses ([D52](0052-agent-identity-by-message-signatures.md)). The key is rotated and revocable. Federation with cloud workload identity may be added later.
- **High availability.** Each pool runs several agent replicas; leases belong to the pool, not to a replica. When a replica fails, another adopts its running jobs by listing them through the backend labels that carry the attempt identifier ([D28](0028-warehouse-connection-policy-and-plan-pinning.md)) and continues renewing their leases.
- **Three contracts.** Versioned separately: the **unit specification** carried in a lease — the compiled and resolved plan for one unit (image digests, segments, input versions and locations, staging location, resources, credential scopes and secret references), not the raw IR, so agents never handle IR migrations; the **agent protocol**, negotiated at connection, with the control plane supporting a window of agent versions because customers upgrade agents on their own schedule; and the **agent–unit contract**, the local endpoint through which a unit fetches its specification, refreshes credentials, sends events, writes checkpoints ([D31](0031-execution-state-model.md)) and requests its commit.
- **Message classes.** State-bearing messages — claims, renewals, state transitions, checkpoint commits, commit requests and end-of-attempt reports carrying outcome and failure class ([D31](0031-execution-state-model.md)) — are guaranteed, idempotent and sequence-numbered per attempt. Telemetry — logs, metrics and progress — is best effort and goes to a configurable sink, the vendor's observability service or the customer's own ([CORE 4.7]({workspace}/documentation#3)), with live tailing proxied through the agent; correctness never depends on it ([D21](0021-architecture-planes.md)). The agent applies the classification filter to previews and samples before anything leaves the customer environment ([D22](0022-deployment-topologies.md)). Amended by [D43](0043-scheduling-and-capacity.md): claims, leases and state-bearing messages carry the attempt's tenant, and the agent keys its credential caches, secret resolution, commit buffers and telemetry routing by tenant, even where it serves one tenant.
- **Amends.** [D21](0021-architecture-planes.md): the control plane leases work with credential scopes and secret references rather than scoped credentials. [D22](0022-deployment-topologies.md): credentials are minted, and secrets resolved, by the agent in every deployment, not only in the hybrid topology. [CORE 7.3]({workspace}/documentation#3): the control plane stores secret references centrally; values are held and resolved in the data plane.
- **Transport.** Settled by [D44](0044-minimum-technology-stack.md): protobuf messages over ConnectRPC, as unary calls for state-bearing messages and one long-poll per agent replica for offered work and control signals, over HTTPS, with no dependence on long-lived HTTP/2 streams. Timings were set by [D43](0043-scheduling-and-capacity.md).
- **Leases and probes.** Amended by [D48](0048-execution-mechanics.md): renewals are held in the leader's memory, an attempt is persisted before it is offered, and every renewal response carries the attempts the agent must stop. Amended by [D49](0049-source-probes.md): source probes are a further kind of offered work.
- **Sessions.** Amended by [D50](0050-development-mode.md): an offered attempt may name a session, in which case the agent delivers its unit specification to the running session container through the agent–unit contract; a session holds its own lease, renewed with the heartbeat; each attempt in a session receives its own credential scopes. A session lease must allow several attempts at once, whether or not sessions run them concurrently.
